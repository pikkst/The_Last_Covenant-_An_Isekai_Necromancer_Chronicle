# Summon Fusion and Evolution

## Purpose

Fusion and evolution let players create unique higher-order summons while preserving the game's themes of identity, consent, memory, and consequence.

Fusion is not a generic duplicate-consumption mechanic.

## Transformation families

### Reinforcement

Improve one summon using materials, body parts, anchors, or ritual work without adding another identity.

### Grafting

Add a compatible physical or metaphysical trait from a donor component.

### Vessel Evolution

Transform the body into an advanced form while retaining the same animating identity.

### Memory Synthesis

Combine selected memory patterns without necessarily merging persons.

### Cooperative Fusion

Two or more consenting identities temporarily or permanently share a form.

### Dominant Fusion

One identity remains primary while another becomes an integrated voice, skill source, or memory layer.

### Composite Birth

Create a new person from multiple contributing patterns. Contributors and the result are legally and narratively distinct.

### Coercive Assimilation

Force one entity into another. Powerful, unstable, and remembered as a serious act.

### Formation Fusion

Multiple bodies temporarily operate as one tactical entity while retaining separate identities.

## Fusion record

- ritual ID;
- participants and components;
- consent/claims;
- intended identity model;
- primary vessel;
- retained/lost traits;
- inherited skills;
- memory policy;
- equipment handling;
- result Name;
- reversibility;
- instability;
- witnesses;
- costs;
- legal/faction consequences;
- deterministic seed;
- outcome history.

## Eligibility

Fusion validates:

- component availability;
- body/spirit compatibility;
- skill and ritual knowledge;
- participant state;
- consent or coercive capability;
- unique-identity rules;
- active promises;
- equipped/bound items;
- anchors;
- territory/facility;
- resource cost;
- content-version support.

## Inheritance

A fusion does not simply sum all stats.

Rules define:

- base structure;
- selected inherited traits;
- capped stat conversion;
- active and dormant skills;
- conflicting traits;
- memory integrity;
- new weaknesses;
- maintenance;
- command cost;
- autonomy.

Players preview known inheritance ranges and guaranteed consequences.

## Skill fusion

Possible results:

- retain skill;
- transform skill;
- unlock hybrid node;
- make skill dormant until compatible equipment;
- lose body-specific skill;
- create conflict requiring resolution;
- inherit a technique as memory rather than mastery.

## Equipment handling

Before fusion:

- unequip ordinary gear where possible;
- identify embedded/attuned/bound items;
- choose inheritance for compatible anchors/relics;
- move incompatible items to inventory;
- define breakage or transformation;
- prevent unique-item duplication.

Equipment embedded in the result becomes part of fusion history and may need special extraction.

## Evolution trees

Example skeletal evolution routes:

- Skeleton -> Bone Guard -> Ossuary Knight -> Grave Captain;
- Skeleton -> Bone Archer -> Marrow Sniper -> Silent Ballista;
- Skeleton -> Ritual Frame -> Bone Channeler -> Walking Reliquary;
- Skeleton cohort -> Formation Fusion -> Bone Colossus.

Routes have skill, body, memory, equipment, title, and story requirements.

## Temporary fusion

Temporary fusion defines duration, damage distribution, shared control, separation conditions, equipment restoration, and emergency failure. It supports tactical forms without permanently erasing individuals.

## Reversal

Possible categories:

- freely separable;
- separable through ritual;
- separable with loss;
- irreversible by known methods;
- metaphysically irreversible.

Irreversible fusion requires explicit confirmation and records the reason.

## Identity conflict

Fusion may create:

- negotiated co-consciousness;
- alternating control;
- memory bleed;
- false continuity;
- new emergent Will;
- internal opposition;
- one identity suppressing another.

These produce authored scenes and mechanics, not random prose.

## Player and companion response

Autonomous summons may request, refuse, regret, or seek reversal. Companions and factions react to the method, consent, bodies used, result, and public legend.

## Fusion failure

Failures may include:

- no transformation;
- partial graft;
- unstable body;
- identity separation;
- hostile composite;
- memory loss;
- anchor fracture;
- equipment damage;
- uncontrolled temporary form;
- permanent consequence when clearly telegraphed.

## Balance

- fusion is not the only path to endgame viability;
- early named summons can evolve without being consumed;
- composite power creates maintenance, autonomy, identity, or tactical tradeoffs;
- there is no loot-box rarity or random duplicate feeding;
- coercive fusion can be strong but never consequence-free.

## UX

Fusion Lab provides:

- participant selection;
- identity/consent summary;
- compatibility;
- known inherited/lost traits;
- skill and equipment handling;
- costs;
- instability;
- reversibility;
- legal/social warnings;
- visual form preview where assets exist;
- irreversible confirmation.

## Testing

Test every fusion family, consent, unique identities, skill inheritance, equipment, temporary separation, death, reversal, autonomy, concurrency, rollback, save migration, and duplication exploits.
